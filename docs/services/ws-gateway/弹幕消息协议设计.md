# 弹幕消息协议设计

## 一、客户端消息

### send_danmaku

用户发送弹幕。

```json
{
  "type": "send_danmaku",
  "request_id": "req_dm_10000001",
  "timestamp": 1780000000000,
  "data": {
    "content": "这个价格可以"
  }
}
```

字段规则：

| 字段 | 规则 |
| --- | --- |
| request_id | 客户端生成，同一次重试保持不变；服务端用于短期幂等 |
| content | 去除首尾空白后长度 1 到 30 个字符 |

处理规则：

1. 未登录用户返回 `401`。
2. 当前连接未绑定有效直播间时返回 `400`。
3. 直播间非 `living` 状态时返回 `403`；不能只依赖连接建立时校验。
4. 内容为空、超长或 JSON 格式错误时返回 `400`。
5. 命中频控时返回 `429`。
6. 相同用户、直播间和 `request_id` 在短时间内重复发送时，返回首次成功生成的 `message_id`，不重复广播。
7. 发送成功后返回 `message_id`，直播间展示以随后广播的 `danmaku_created` 为准。

成功响应：

```json
{
  "type": "response",
  "request_id": "req_dm_10000001",
  "request_type": "send_danmaku",
  "code": 0,
  "message": "success",
  "server_time": 1780000001000,
  "data": {
    "message_id": "dm_10000001",
    "room_id": 4001
  }
}
```

## 二、连接成功响应

用户连接成功后，`connect` 响应的 `data` 中补充最近弹幕：

```json
{
  "recent_danmaku": [
    {
      "message_id": "dm_10000001",
      "sender_type": "user",
      "user_id": 9001,
      "nickname": "张三",
      "content": "这个价格可以",
      "content_type": "text",
      "server_time": 1780000001000
    }
  ]
}
```

第一版不新增 HTTP 历史弹幕接口。客户端进入直播间时，通过 WebSocket 连接成功响应获取最近 10 条弹幕；断线重连后同样以连接响应中的最近弹幕作为轻量补偿。

返回顺序固定为按 `server_time` 正序，即旧消息在前、新消息在后，方便前端按列表顺序追加渲染。

## 三、服务端广播

### danmaku_created

普通用户弹幕广播。

```json
{
  "type": "danmaku_created",
  "event_id": "evt_dm_10000001",
  "room_id": 4001,
  "server_time": 1780000001000,
  "data": {
    "message_id": "dm_10000001",
    "sender_type": "user",
    "user_id": 9001,
    "nickname": "张三",
    "content": "这个价格可以",
    "content_type": "text",
    "status": "visible"
  }
}
```

### ai_interaction_created

AI 互动助手消息广播。

```json
{
  "type": "ai_interaction_created",
  "event_id": "evt_ai_10000001",
  "room_id": 4001,
  "server_time": 1780000005000,
  "data": {
    "message_id": "ai_msg_10000001",
    "sender_type": "ai_assistant",
    "assistant_role": "ai_interaction",
    "display_name": "AI互动助手",
    "content": "这件商品的加价规则是每次至少加 100 元。",
    "content_type": "text",
    "status": "visible"
  }
}
```

AI 消息必须满足：

1. `sender_type` 固定为 `ai_assistant`。
2. 不使用真实用户 `user_id`。
3. 前端展示时必须与普通用户弹幕区分。

## 四、错误码

在现有错误码基础上新增：

| code | 说明 |
| --- | --- |
| 429 | 弹幕发送过于频繁 |

其他错误码沿用 `ws-gateway` 现有约定：

| code | 场景 |
| --- | --- |
| 400 | 消息格式错误、内容为空、内容超长 |
| 401 | 未登录 |
| 403 | 直播间不允许发送 |
| 500 | 必要依赖不可用或内部处理失败 |
