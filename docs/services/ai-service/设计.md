# ai-service 核心设计

> Status: proposed
> Authority: 本文负责 AI 输入消费、场次执行器、窗口、候选、调度、决策和回写实现。
> Non-authority: Tool/RAG 和模型安全分别见专题文档；阶段定义见统一实施路线。
> Updated-at: 2026-07-17 +08:00

## 一、P0 拓扑

```text
64 logical input buckets
          |
          v
 InputSubscriber (one instance subscribes all)
          |
     SessionDispatcher
          |
 SessionAgent per live_session_id
 filter -> short window -> candidate -> route -> tools -> model -> guard
          |
 InteractionClient.PublishAssistantMessage
```

P0 明确只运行一个 AI 消费实例，不实现 bucket 租约或 leader election。64 分片契约从第一天固定，扩容时只替换 bucket ownership 实现。

## 二、稳定接口

| 接口 | P0 实现 | 可替换方向 |
| --- | --- | --- |
| `InputSubscriber` | Redis Pub/Sub 全 bucket 订阅 | 多实例 bucket ownership |
| `RoomPolicyProvider` | live-service gRPC + 有界缓存 | 配置/策略聚合服务 |
| `SessionDispatcher` | 本地 map + 串行 executor | 分布式所有权 |
| `CandidateSelector` | 规则、相似归一和阈值 | 轻量分类/Embedding |
| `Scheduler` | 有界优先队列 | 跨房间公平调度 |
| `KnowledgeRouter` | 规则路由 | 受控分类器/复杂 Agent |
| `ToolProvider` | gRPC Tool adapter | 聚合 Tool service |
| `ModelProvider` | 单模型结构化生成 | 多模型路由 |
| `InteractionClient` | gRPC 回写 | 契约保持不变 |
| `DecisionAudit` | 脱敏结构日志/存储 | 可靠审计旁路 |

接口稳定不要求 P0 实现右侧复杂能力。

## 三、输入消费

`InputSubscriber` 只接受共享契约 v1 的事件，并按以下顺序快速拒绝：

1. schema/event type 不支持。
2. 非真人消息、缺 session、已经过期。
3. AI 全局关闭。
4. `event_id/message_id` 在短期本地去重缓存命中。
5. 本地队列已满且候选优先级不足。

Pub/Sub 回调不调用模型和业务 Tool，只做校验与投递，避免阻塞同连接的其他 bucket。

`SessionDispatcher` 在创建/刷新 SessionAgent 前通过 `RoomPolicyProvider` 解析 `room_id -> shop_id/current_live_session_id/AI policy`，并校验事件 session。结果以 `room_id + live_session_id` 为键做短 TTL 缓存；缺失、超时、session 不匹配或 room/shop 不在 allowlist 时 fail closed。共享消息不增加可伪造或易陈旧的 `shop_id`，权威归属始终来自 live-service。

## 四、SessionAgent

每个活跃 `live_session_id` 对应一个逻辑 SessionAgent，同一时刻只由一个串行执行器修改本地状态：

```text
session identity
room/shop policy snapshot
recent normalized messages (bounded)
open aggregation windows (bounded)
recent answered intent fingerprints (bounded)
last answer time / current inflight task
context version and expiry
```

Agent 同时校验消息中的 `room_id`；同一 session 观察到另一个 room 时视为契约错误并丢弃。场次空闲超时或收到结束信号后释放本地状态，任何恢复都从空上下文开始，不回放积压。

## 五、过滤与短窗口

### 5.1 规则过滤

优先过滤不需要模型的消息：纯表情、无语义短词、刷屏、广告、明显攻击、重复粘贴和已过期消息。风险问题不进入普通回答，可标记为 `REDIRECT` 候选。

### 5.2 聚合

以数百毫秒的可配置短窗口聚合同一场次的消息，规范化大小写、空白和常见口语后计算相似意图。窗口只保存有界数量，溢出时优先淘汰低价值和最旧候选。

相似问题形成一个 `QuestionCluster`：代表消息、关联消息 ID、重复人数、最近时间、推测路由和风险标签。聚合不是聊天历史，也不跨 session。

## 六、候选与调度

候选评分至少考虑：

- 是否明确提问且能够公开回答。
- 多人重复受益、与当前商品/竞拍相关、时效性。
- 是否已有回答、是否在冷却、资料是否可得。
- 风险、冒犯、隐私和模型成本。

P0 `Scheduler` 使用有界优先队列和全局并发 semaphore。队列等待超过新鲜度直接丢弃；同一 session 同时最多一个生成任务。低分候选不因等待时间无限晋升。

## 七、防重与冷却

P0 虽是单实例，仍从第一天使用 session-scoped Redis 状态，为崩溃恢复和以后扩容保留稳定语义：

| Key | 作用 |
| --- | --- |
| `ai:{session:<id>}:inflight` | 有 TTL 的生成锁 |
| `ai:{session:<id>}:cooldown:answer` | 场次回答冷却 |
| `ai:{session:<id>}:answered:<intent_hash>` | 已回答意图预留/抑制 |

流程为：获取 inflight → 原子预留 intent → 获取知识并生成 → 成功回写后设置冷却 → 释放 inflight。失败时根据失败类别释放或保留短 TTL，避免故障风暴。

`decision_id` 在真正决定发布时生成，之后所有 gRPC 结果未知重试复用同一 ID。两个独立任务的 `decision_id` 不同，因此真正的跨任务防重依赖 inflight、intent 预留和冷却。

## 八、确定性决策流水线

P0 不使用让模型自由循环调用工具的 Agent：

1. 规则或轻量分类器先输出 `route`、风险和是否值得回答。
2. `KnowledgeRouter` 根据 route 调用固定白名单 Tool。
3. Tool adapter 返回安全投影、事实时间和版本。
4. `ModelProvider` 使用问题、有限上下文和事实进行一次结构化生成。
5. Guard 校验动作、长度、事实支持、安全和新鲜度。
6. 有可发布动作时生成 `decision_id`，通过 interaction gRPC 回写。

这条路径让大多数候选最多调用一次模型。资料不足时直接 `NO_REPLY/REDIRECT`，不让模型自行猜测工具或参数。

## 九、模型输出

模型输出解析为内部对象，不直接使用自由文本：

```text
action: NO_REPLY | ANSWER | REDIRECT
content: string
confidence: number
fact_keys: []string
risk_flags: []string
```

`confidence` 只用于服务端策略，不能作为事实正确性的唯一依据。`fact_keys` 必须能映射到本次 Tool 安全投影；动态事实回答缺少对应 key 时拒绝。

## 十、回写与重试

回写前再次检查任务截止时间、session 本地状态和 AI 开关。interaction-service 负责最终 session 校验、硬上限和规范消息生成。

只对 `Unavailable` 或超时结果未知进行少量退避重试，并复用 `decision_id`。`FailedPrecondition`、`PermissionDenied`、`ResourceExhausted` 和内容错误是确定拒绝，不更换 ID 重试。

成功只表示 interaction 接纳，不等待客户端收到。AI 不订阅自身输出作为可靠确认；可以通过审计中的 message ID 关联决策。

## 十一、故障与背压

| 故障 | 行为 |
| --- | --- |
| Redis 输入断线 | 重连后继续新消息，不追补断线窗口 |
| Session 队列满 | 丢弃低优先级/最旧任务并计数 |
| Tool 超时 | `NO_REPLY` 或安全 `REDIRECT`，不猜测 |
| 模型超时/限额 | 放弃任务，释放或短暂保留锁 |
| interaction 不可用 | 新鲜度内原 ID 重试，过期放弃 |
| session 结束/切换 | 取消在途任务；最终回写仍由 interaction 拒绝 |

任何 AI 故障都不能向 interaction 用户写路径施加同步依赖。

## 十二、水平扩展接口

需要多实例时，增加 bucket lease/ownership，实例只订阅持有的逻辑 bucket。租约短暂重叠仍可能产生两个消费者，因此 session inflight 和意图预留继续作为最终防重；不能依赖 `decision_id`。

扩容不改变输入频道、散列算法、SessionAgent 语义或回写 RPC。具体启用阶段只在 [实施路线](../../features/live-interaction/实施路线.md) 中维护。
