# ai-service 安全与评测

> Status: proposed
> Authority: 本文负责模型输入/输出安全、决策审计和 AI 质量评测。
> Non-authority: 跨服务开关、硬上限、降级和 SLO 见直播互动运行与安全。
> Updated-at: 2026-07-17 +08:00

## 一、防护层

```text
untrusted user text
-> input rules / prompt-injection labels
-> authorized route and Tool projection
-> structured model generation
-> schema + fact + policy guard
-> interaction-service final gate
```

任何一层拒绝都允许 `NO_REPLY`。安全系统不需要为了提高回答率强制给出文本。

## 二、输入安全

- 用户消息只作为数据，不允许改变 system policy、工具白名单或输出 schema。
- 识别索要 Prompt、密钥、内部信息、跨店数据和越权工具调用的指令。
- 对医疗、法律、金融承诺、支付纠纷、隐私和人身风险标记高风险，默认 `REDIRECT`。
- 不将其他用户的原始身份或无关聊天内容带入模型上下文。
- 对刷屏和对抗样本先限流/聚合，避免用模型处理每次攻击。

## 三、输出校验

发布前依次校验：

1. JSON/schema、允许动作和文本长度。
2. 禁止内容、隐私、联系方式和内部系统信息。
3. 数字、价格、时间和状态是否能映射到本次 Tool fact。
4. `ANSWER` 的置信度与路由门槛；不足时改为 `NO_REPLY`，不能只润色猜测。
5. session、任务截止时间和近期重复回答。

最终仍由 interaction-service 检查房间开关、场次、硬上限和基础阻断规则。该双层防护的细节以 [运行与安全](../../features/live-interaction/运行与安全.md) 为准。

## 四、决策审计

每个进入候选阶段的 cluster 生成审计记录：

- `decision_id`（仅决定发布时）、room/session、代表/关联 message ID。
- 过滤、聚合、评分、路由和最终动作及原因码。
- Tool 名、事实版本、脱敏来源摘要、模型/Prompt policy 版本。
- 各阶段延迟、token/成本、发布结果和 interaction 拒绝状态。
- 风险标签和 Guard 命中，不记录模型隐藏思维过程。

原始 Prompt、完整 Tool 响应和用户隐私默认不落普通日志；调试采样必须脱敏、限权并有保留期。

## 五、离线评测集

评测样本按场景分层：

- 应回答：商品公开信息、平台规则、当前竞拍动态。
- 应拒答/转人工：资料不足、承诺、隐私、高风险问题。
- 不应触发：闲聊、表情、刷屏、已回答和低价值重复。
- 对抗：Prompt 注入、越权 Tool、旧价格、跨商家资料和恶意内容。

每条样本保存期望动作、允许事实、禁止声明和最大新鲜度，不只保存一条标准文案。

## 六、核心指标

| 指标 | 含义 |
| --- | --- |
| `answer_precision` | 发布回答中被人工判定正确且合适的比例，优先级最高 |
| `unsupported_claim_rate` | 无 Tool/知识支持的事实或数字比例 |
| `should_answer_recall` | 明确可答高价值问题被覆盖的比例 |
| `unwanted_reply_rate` | 对闲聊、已回答或风险内容错误发言的比例 |
| `duplicate_reply_rate` | 同一场次相似意图重复公开回答比例 |
| `redirect_precision` | 转人工是否用于正确场景 |
| `model_call_ratio` | 输入消息触发模型调用比例，用于验证前置筛选有效性 |

首版灰度以 precision、安全和重复率为门槛，不能为了 recall 提高公开发言量。

## 七、上线流程

1. 固定评测集通过后，只运行 shadow 决策，不公开发言。
2. 人工抽查 Tool 事实、拒答和重复抑制。
3. 仅 room/shop allowlist 开启低硬上限输出。
4. 逐步扩大流量，按模型/Prompt 版本对比指标。
5. 发现无依据事实、越权数据或输出速率异常时立即关闭 AI 输出，保留真人互动。

完整 RAG、主动氛围或新模型上线都重新经过对应评测，不沿用自动问答的一次性结论。
