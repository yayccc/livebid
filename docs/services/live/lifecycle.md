# Live Service 生命周期

## 状态

第一版只保留两个主状态：

| 状态 | 说明 |
| --- | --- |
| `not_live` | 未直播 |
| `living` | 直播中 |

允许流转：

```text
not_live -> living
living -> not_live
```

约束：

- `not_live` 可以编辑直播间基础信息。
- `not_live` 可以开始直播。
- `living` 可以结束直播。
- 只有 `living` 可以开始竞拍。
- 结束历史不进入主状态机，用时间字段表达。

## 创建直播间

输入：

- 标题。
- 封面，可选。
- 简介，可选。

创建时由当前登录身份确定 `shop_id`，并生成：

- `stream_name`。
- `stream_code`。
- RTMP 推流地址。
- WebRTC 播放地址，第一版可同时用于商家预览和用户播放。

创建后状态为 `not_live`。

## 修改直播间

`not_live` 状态允许修改：

- 标题。
- 封面。
- 简介。

直播中是否允许修改标题、封面和简介暂未确定。

## 开始直播

开始直播时：

- 校验直播间存在。
- 校验直播间归属当前商铺。
- 校验状态是 `not_live`。
- 写入实际开播时间。
- 状态改为 `living`。
- 发布 `live.started` 事件。

重复开始直播需要幂等。如果直播间已经是 `living`，返回当前直播状态。

第一版商家点击开始直播后，业务状态即为 `living`。SRS 是否真的收到推流，由 `media_stream_status` 表达。

## 结束直播

结束直播时：

- 校验直播间存在。
- 校验直播间归属当前商铺。
- 校验状态是 `living`。
- 校验是否存在进行中的竞拍。
- 写入实际关播时间。
- 状态改回 `not_live`。
- 发布 `live.ended` 事件。

第一版建议如果存在 `running` 竞拍，不允许直接关播。商家需要先落锤、流拍或取消竞拍。
