# 直播间弹幕需求（ws-gateway V1 归档）

> Status: superseded。本文只追溯 ws-gateway V1，不能指导新实现。现行目标见 `docs/features/live-interaction/README.md`。

## 一、目标

直播间弹幕用于支持用户在观看直播竞拍时进行实时互动。弹幕不参与竞拍规则、出价判定、成交和订单流程，只作为直播间互动消息展示。

本期目标：

1. 用户可以在直播间发送文本弹幕。
2. 同一直播间在线用户可以实时看到弹幕。
3. 弹幕发送需要基础准入、频控和内容校验。
4. 弹幕消息需要支持紧邻排期的 AI 互动助手消费，用于用户问题识别、直播间氛围辅助和互动分析。
5. 后续可以扩展禁言、撤回、审核、历史查询和运营治理能力。

## 二、用户场景

1. 用户进入直播间后，可以看到其他用户发送的弹幕。
2. 登录用户可以发送弹幕。
3. 游客用户第一版只允许观看弹幕，不允许发送。
4. 用户发送弹幕后，直播间内其他在线用户应尽快看到。
5. 用户刚进入直播间时，可以看到少量最近弹幕，用于感知直播间互动氛围。
6. 如果用户发送过快、内容为空、内容过长或命中基础规则，服务端应拒绝发送并返回原因。
7. AI 互动助手可以基于用户弹幕识别问题并生成回复或场控建议，但 AI 消息必须明确标识 AI 身份。

## 三、功能范围

### 本期实现

1. 支持文本弹幕发送。
2. 支持直播间维度弹幕广播。
3. 支持最近弹幕展示，第一版默认展示最近 10 条。
4. 支持用户维度发送频控。
5. 支持弹幕内容长度限制和空内容过滤。
6. 支持基础敏感词或违规词拦截。
7. 弹幕消息包含发送用户、直播间、内容、发送时间和消息 ID。
8. 支持将弹幕消息作为 AI 互动助手的输入来源，并提供给 `ai-service` 消费。

### 本期不实现

1. 不支持图片、表情包、语音、视频等富媒体弹幕。
2. 不支持私聊。
3. 不支持完整历史弹幕查询。
4. 不支持离线弹幕补发。
5. 不支持管理员撤回。
6. 不支持 AI 异步审核闭环。
7. 不支持复杂用户分层展示策略。
8. 不在 `ws-gateway` 内实现 AI 互动助手自动回复策略、主动氛围消息策略或商家确认流程；`ws-gateway` 只提供 AI 消息回到直播间展示的传输通道。

## 四、业务规则

1. 发送弹幕必须绑定当前直播间，客户端不能自行指定其他直播间。
2. 只有直播中的直播间允许发送弹幕；如果直播已结束但 WebSocket 连接尚未断开，发送弹幕时仍必须拒绝。
3. 发送弹幕必须登录；未登录用户发送时返回未登录错误。
4. 弹幕内容去除首尾空白后不能为空。
5. 弹幕内容长度第一版限制为 1 到 30 个字符。
6. 同一用户在同一直播间内需要限制发送频率，具体阈值后续配置化。
7. 命中频控或内容规则时，弹幕不广播。
8. 弹幕展示不影响竞拍消息；竞拍价格、成交、倒计时等消息优先级高于弹幕。
9. 用户昵称优先在连接建立或首次发送弹幕时缓存，弹幕广播时不再频繁查询用户服务。
10. 弹幕第一版不展示用户头像。

## 五、消息内容

弹幕消息建议包含：

| 字段 | 说明 |
| --- | --- |
| message_id | 弹幕消息 ID |
| room_id | 直播间 ID |
| user_id | 发送用户 ID |
| nickname | 用户昵称 |
| content | 弹幕文本 |
| content_type | 内容类型，第一版固定为 text |
| server_time | 服务端时间 |
| status | 消息状态 |

## 六、后续扩展

1. 房间禁言和全局禁言。
2. 管理员撤回弹幕。
3. 弹幕长期存储和运营后台查询。
4. 异步风控审核和 AI 审核。
5. AI 互动助手消费弹幕，用于回答用户问题、识别直播间互动热点、生成主播话术建议和低频氛围消息。
6. 直播间热度、互动量和用户行为统计。
7. 高热直播间弹幕限流、降采样和优先级策略。

## 七、AI 互动助手对接边界

弹幕系统不判断 AI 互动助手哪些问题可以自动回复，也不处理商家或主播确认流程。这些策略由 `ai-service` 和商家后台负责。

弹幕系统只需要支持：

1. 将用户弹幕作为事件提供给 `ai-service` 消费。
2. 支持 AI 互动助手生成的直播间消息回到当前直播间展示。
3. AI 消息必须和普通用户弹幕区分，不能伪装成真实用户。
